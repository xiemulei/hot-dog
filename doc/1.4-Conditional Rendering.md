# 条件渲染

到目前为止，我们的用户界面一直相当静态。然而，我们使用 Dioxus 构建的大多数应用通常包含大量动态内容。我们的 UI 会响应按钮、表单输入、滑块或网络等外部数据源的变化而作出反应。Dioxus 应用一般会将这种动态状态存储在 Hooks 或 Context 中。

在本章中，我们不会深入探讨如何存储这些状态——有关状态的详细内容将在后续章节中介绍。

## 表达式

与 JSX 类似，RSX 允许您使用纯 Rust 代码轻松地将 Element 对象组合在一起。您可以在 RSX 中直接编写 Rust 表达式。只要表达式的计算结果是 Element，或者实现了 IntoDynNode trait 的任何类型，您只需将其包裹在大括号（`{}`）中即可：

```rust
let content = "world!";
rsx! {
    h1 {
        "Hello"
        {content}
    }
}
```

例如，我们可能需要从一些复杂的格式化函数中生成一个字符串：

```rust
rsx! {
    span {
        {
            format!(
                "The time is: {now}, your timezone is {zone}",
                now = current_time(),
                zone = current_timezone()
            ).to_ascii_uppercase()
        }
    }
}
```

或者，我们可能希望动态渲染一些 RSX 并将其赋值给一个变量：

```rust
let header = match current_timezone() {
    TimeZone::PST => rsx! {
        h1 { "Welcome home" }
    },
    _ => rsx! {
        h1 { "Bon voyage!" }
    },
};

rsx! {
    div {
        {header}
    }
}
```

Rust 的表达式系统使得从 match 语句和 if 块中评估 RSX 变得非常方便。而在 JavaScript 中，您可能会用三元运算符：

```js
let screen = authenticated ? renderApp() : renderLogin();

return <div>{screen}</div>;
```

但在 Dioxus 中，您只需简单地使用 if/else 语句：

```rust
let screen = if authenticated { render_app() } else { render_login() };
rsx! {
    div {
        {screen}
    }
}
```

Rust 的 guard 条件在这种场景中尤其有用，让我们能够通过内联 if 语句来选择匹配分支：

```rust
let header = match current_timezone() {
    TimeZone::PST => rsx! {
        h1 { "Welcome home" }
    },
    _ if app.snoozed() => rsx! {
        h1 { "snoozed..." }
    },
    _ => rsx! {
        h1 { "Bon voyage!" }
    },
};

rsx! {
    div {
        {header}
    }
}
```

## IntoDynNode Trait

Dioxus 使用 [IntoDynNode](https://docs.rs/dioxus-core/latest/dioxus_core/trait.IntoDynNode.html) trait 来判断某个表达式是否能在 RSX 中使用。该转换会将一个 Rust 表达式转化为四种 DynamicNode 变体之一：

- Component：接受属性并渲染 Element 的函数
- Text：Rust 的 String 类型
- Placeholder：优化后的 None 值
- List：Element 的 Vec

许多类型都实现了这个 trait。例如，空表达式是合法的：

```rust
rsx! {
    div {
        { /* empty.. */}
    }
}
```

其他 Element 对象也是合法的：

```rust
let inner = rsx! { "inner" };
rsx! {
    div {
        {inner}
    }
}
```

所有字符串类型（str、String、Arguments）都是合法的：

```rust
rsx! {
    div {
        // Strings
        {"abc"}

        // lazy formatting
        {format_args!("lazy fmt -> {}", arg())}
    }
}
```

Rust 的 Option 类型也是合法的，前提是其内部类型实现了 IntoDynNode：

```rust
let inner = Some(rsx! { "inner" });
rsx! {
    div {
        {inner}
    }
}
```

甚至迭代器也可以通过 List 变体变成 VNode：

```rust
let cards = (0..10).map(|i| rsx! {
    li { "Card: {i}" }
});

rsx! {
    ol {
        {cards}
    }
}
```

迭代器特别有趣，因为 IntoDynNode 为任何迭代器类型都实现了这一 trait。例如，我们可以构建一个自定义迭代器，使其返回一个 Element：

```rust
let mut count = 0;
let cards = std::iter::from_fn(move || {
    count += 1;
    if count > 6 {
        return None;
    }

    Some(rsx! { "card {count}" })
});

rsx! {
    ol {
        {cards}
    }
}
```

## 内联 If 语句

当渲染基于布尔条件的内容时（例如，"active" 或 "inactive"），RSX 提供了一些小"语法糖"，支持在 RSX 中使用内联 if 语句：

```rust
let logged_in = use_signal(|| false);

rsx! {
    div {
        if logged_in() {
            "You are logged in"
        } else {
            "You are not logged in"
        }
    }
}
```

请注意，内联 if 语句的主体部分是 RSX，而不是 Rust 表达式。这种语法糖有助于保持 RSX 块的整洁和惯用风格。

```rust
rsx! {
    div {
        if logged_in() {
            LoggedInScreen{}
        } else {
            LoggedOutScreen{}
        }
    }
}
```

内联 if 语句与 Rust 有一点不同：即使没有 else 分支，它们依然会计算出一个 Element。如果 RSX 在您的 if 语句中没有找到 else 分支，它会自动返回一个占位符元素。

```rust
rsx! {
    div {
        if logged_out() {
            span { "You should log in!" }
        }
    }
}
```

## 更多语法糖？

语法是非常主观的，像内联 if 和 for 块这样的语法糖可能会导致行为不一致。我们并不打算在 RSX 中引入更多的语法糖。我们的目标是在保持与 React 的 JSX 相似性的同时，稍微调整一下对 Rust 开发者的友好度。

RSX 的语法经过精心设计，能很好地配合您的常规开发流程：

- 输入 RSX 元素时，只需输入名称，然后紧跟一个大括号
- RSX 无需额外的编辑器扩展即可获得出色的语法支持
- RSX 遵循 Rust 的标记化规则，实现自动高亮和代码折叠功能

请务必花些时间熟悉 RSX，感受它的独特魅力。
