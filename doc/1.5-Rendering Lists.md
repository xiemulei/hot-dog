# 渲染列表

## 迭代器与内联 for 循环

在[`条件渲染`](./1.4-Conditional%20Rendering.md)章节中，我们展示了 Rust 表达式如何在 RSX 块中成为动态节点。

任何返回 `Element` 或实现了 `IntoVnode` 的对象的迭代器，都可以在 RSX 块中用于渲染列表：

```rust
rsx! {
    // mapping existing iterators
    {(0..10).map(|idx| rsx! { "item {idx}" })}

    // or calling .iter()
    {users.iter().map(|user| rsx!{ User { id: user.id } })}
}
```

Dioxus 提供了一小部分语法糖，让使用迭代器变得更加便捷。你无需将迭代器包裹在表达式中，而是可以直接将其移到内联 `for` 循环块中：

```rust
rsx! {
    for idx in 0..10 {
        "Item {idx}";
    }

    for user in users.iter() {
        User { id: user.id }
    }
}
```

与内联 `if` 块类似，`for` 循环的主体也是 RSX 代码——而非 Rust 表达式。如果你需要在迭代过程中创建临时变量或执行一些额外计算，可以使用内联表达式：

```rust
rsx! {
    for user in users.iter() {
        {
            let id = user.id();
            rsx! {
                User { id }
            }
        }
    }
}
```

如果我们同时使用迭代器和像 `Signal<T>` 这样的包装类型，则需要先调用 `.iter()` 方法：

```rust
let mut items = use_signal(|| vec!["Hello", "Dioxus"]);

rsx! {
    ul {
        for item in items.iter() {
            li { "{item}" }
        }
    }
}
```

## 必须提供键值

你的列表中的每个项都应有一个唯一且在重新渲染时保持稳定的值，称为"键"（key）。键用于标识项在不同渲染之间如何移动。如果没有键，当你重新排序列表中的项时，很容易意外丢失或移动状态。我们可以通过使用 `key` 属性为列表项添加键：

```rust
let mut items = use_signal(|| vec!["Hello", "Dioxus"]);

rsx! {
    ul {
        for item in items.iter() {
            li { key: "{item}", "{item}" }
        }
    }
}
```

通常，你可以从状态本身找到一个合适的键。UI 中的大多数数据都有某种唯一标识符，可用于将其与其他集合项区分开来。例如，用户通常拥有唯一的 ID，时间样本拥有唯一的时间戳，电子邮件则有唯一的发件人地址。

```rust
rsx! {
    for user in users {
        div { key: "{user.id}", "{user.name}" }
    }
}
```

需要注意的是，某些字段看似适合用作唯一 ID，但实际上并不合适。两个用户可能共享相同的姓名，两个数据点可能共享相同的时间戳，或者并非每个条目都实际包含所需的数据。在这种情况下，我们建议根据全局"生成"（generation）计数器为每个项创建一个唯一 ID。通常，数据库会提供这一功能，但我们也可以使用状态来管理：

```rust
let mut generation = use_signal(|| 0);
let mut items = use_signal(|| vec![]);

let mut add_item = move |name| {
    let id = generation();
    generation.set(id + 1);
    items.write().push(Item { id, name })
};

rsx! {
    for item in items.iter() {
        div { key: "{item.id}", "{item.name}" }
    }
    // ...
}
```

最糟糕的键值是集合中项的索引。随着列表的变更，项的索引也会改变，这几乎肯定会引发性能问题或组件中的状态丢失。

```rust
// ❌ 不要这样做！
rsx! {
    for (idx, user) in users.iter().enumerate() {
        div { key: "{idx}", "{user.name}" }
    }
}
```

## Fragment 组件

在某些情况下，你的迭代器可能会返回多个根元素。这使得我们很难为这些元素指定键值。如果存在第一个元素的键，RSX 会自动将其用作迭代器的键：

```rust
rsx! {
    for item in items.iter() {
        h1 { key: "{item.id}", "{item.name}" }
        p { "content" }
    }
}
```

如果没有简单的方法为第一个元素附加键，你可以使用 `Fragment` 组件将这些元素包裹起来，并为其指定键：

```rust
rsx! {
    for item in items.iter() {
        Fragment {
            key: "{item.id}",
            for child in item.children.iter() {
                div { "{child}" }
            }
        }
    }
}
```

`Fragment` 组件本身并没有什么特别之处。它只是一个简单地将其子节点作为自身内容转发的组件。不过，RSX 将其视为有效的元素语法，并能够正确地分配键值。

```rust
#[component]
fn Fragment(children: Element) -> Element {
    children
}
```

## 借用状态

在渲染列表时，你可能希望将部分数据内容借给子组件。常见的 Dioxus 容器 `Signal` 本身并不支持向子组件提供引用。

```rust
let items = use_signal(|| vec![]);

rsx! {
    for item in items.iter() {
        Card {
            // ❌ 无法将引用转发给子组件
            content: item.name.as_str()
        }
    }
}
```

尽管 Dioxus 早期版本曾允许转发引用，但我们最终禁用了这一功能，因为它依赖于一些不安全的 Rust 语义。因此，我们推荐以下三种策略：

- 使用拥有的数据，如果复制开销较小则进行克隆
- 将集合和索引传递给组件
- 使用 `Store` 为集合中的数据切片提供响应式引用

`Store` 使我们能够高效地聚焦到响应式状态。关于 `Store` 的详细内容将在 [Store](/learn/0.7/essentials/basics/collections) 章节中介绍，这里先快速预览一下如何使用它们：

```rust
fn app() -> Element {
    let mut vec = use_store(|| vec![]);

    rsx! {
        div {
            // 迭代一个 store 会为 store 中的响应式项提供引用
            // 而无需克隆它们。
            for count in vec.iter() {
                Child { count }
            }
        }
    }
}

#[component]
fn Child(count: ReadSignal<i32>) -> Element {
    rsx! { "{count}" }
}
```

对于复杂的应用，我们建议围绕全局上下文构建系统，或者直接使用 Store。
