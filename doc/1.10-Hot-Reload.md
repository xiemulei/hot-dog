# Dioxus 热重载参考指南

Dioxus 热重载引擎功能强大无比。正确使用时，它能为采用 Rust 构建应用提供最快速的开发体验。

> Dioxus 0.5 曾推出过有限的热重载功能，而 Dioxus 0.6 则对其进行了大幅改进。
>
> Dioxus 0.7 引入了实验性的 Rust 热重载功能，使其成为首个支持实际 Rust 代码热重载的 Rust 框架。🎉🎉

## RSX 热重载

RSX 热重载是 Dioxus 开发体验的核心。它允许您即时添加、删除或修改 `rsx!` 块中的元素。RSX 解析器不仅在编译时工作，也在我们的开发工具中运行，让 DX 完全无需重新编译您的 Rust 代码。

```rust
fn App() -> Element {
    rsx! {
        // 您可以添加、删除或修改任意元素
        div { class: "container" }
        h1 { "我的应用" }
        button { "点击我" }
    }
}
```

所有基于字符串的属性都支持即时热重载：

```rust
fn Button() -> Element {
    rsx! {
        button {
            // 所有这些都可以即时热重载
            class: "btn btn-primary",
            id: "my-button",
            title: "点击这个按钮",
            style: "background: blue; color: white;",
            "提交"
        }
    }
}
```

热重载支持修改 RSX 中任何位置的复杂格式化字符串。虽然您无法即时热重载内部的 Rust 表达式，但您可以将现有表达式移动到不同格式化字符串之间。

```rust
fn Counter() -> Element {
    let count = use_signal(|| 0);

    rsx! {
        div {
            // 我们可以将这个 `count` 变量从这里移动到
            "计数：{count}"
            button {
                // ... 到这里，完全无需重新编译！
                "增加 ({count})"
            }
        }
    }
}
```

您可以热重载作为组件 props 传递的简单 Rust 表达式。如果属性值是一个 Rust 字面量——比如数字、布尔值或字符串等单个标记——DX 将通过重新解析新属性并就地修改组件的 props 来实现热重载。

```rust
fn App() -> Element {
    rsx! {
        MyButton {
            text: "点击我", // 尝试改为 text
            enabled: true, // 尝试将 true 改为 false！
            count: 123, // 或者改为数字值！
        }
    }
}

#[component]
fn MyButton(text: String, enabled: bool, count: i32, color: String) -> Element {
    rsx! {
        button { disabled: !enabled, "{text} - {count}" }
    }
}
```

热重载适用于条件块、循环以及组件子节点内部。请注意，内部表达式不支持即时 RSX 热重载，但内部元素和标记则支持。

```rust
fn TodoList() -> Element {
    let todos = use_signal(|| vec!["学习 Dioxus", "构建一个应用"]);

    rsx! {
        ul {
            // 我们可以修改 *主体*
            for (i, todo) in todos().iter().enumerate() {
                li {
                    key: "{i}",
                    class: "todo-item",
                    "{todo}"
                }
            }
        }

        // 条件块的主体也支持热重载
        if todos().len() > 5 {
            div { class: "warning", "你有很多待办事项！" }
        }
    }
}
```

## 需要完整重建的情况（或热补丁！）

尽管 RSX 热重载功能强大，但某些更改仍需要完整重建应用：

- 新变量或表达式未出现在上次编译中。
- RSX 外部的逻辑变更（函数体、钩子等）。
- 组件签名（添加或删除 props）。
- 导入语句和模块结构。
- 属性中涉及函数调用的复杂 Rust 表达式。

当启用 `--hotpatch` 标志进行 Rust 热补丁时，DX 将就地修改您应用的汇编，而无需完整重建。启用热补丁后，DX 很少会触发完整重建。您可以在 DX TUI 打开时，随时按 `r` 键手动强制应用进行完整重建。

## 实验性：Rust 热补丁

Dioxus 0.7 新增了实验性的 Rust 代码热重载功能，可通过 `--hotpatch` 标志启用。这一功能具有革命性意义——让您无需重新编译即可修改 Rust 逻辑并立即看到变化。

要使用 Rust 热重载，请运行 `dx serve --hotpatch`。在热补丁功能仍处于实验阶段时，必须使用额外的标志，不过我们计划在未来将其设为默认。

这套名为 Subsecond 的系统能够热重载大部分 Rust 代码的更改。不过，目前仍有一些限制：

- 您可以在运行时添加新的全局变量，但它们的析构函数永远不会被调用。
- 全局变量会在补丁间被追踪，但重命名会被视为引入了一个新的全局变量。
- 对静态初始化器的更改不会被观察到。

另外，最重要的是，Rust 热补丁目前仅跟踪项目中的主 crate。如果您编辑了依赖项中的代码——这可能是工作区中的某个 crate——DX 不会记录这些更改。虽然 RSX 热重载可在整个工作区中生效，但 Subsecond 目前还不支持这一点。

Subsecond 也可用于 Dioxus 之外的场景。许多项目已经采用了 Subsecond 库来实现 Rust 热重载。例如，Bevy 和 Iced 已经集成了 Subsecond。

## 资源热重载

资源热重载让您无需重建应用即可修改 CSS、图片及其他静态文件。这项功能与 `asset!()` 宏系统无缝配合。

### CSS 热重载

CSS 文件会自动被监听，并在更改时即时热重载：

```rust
fn App() -> Element {
    rsx! {
        // 编辑这个样式表将导致运行中的应用即时更新
        Stylesheet { href: asset!("/assets/main.css") }
        div { class: "my-component", "你好，世界！" }
    }
}
```

```css
/* 在 assets/main.css 中——这里的更改会即时生效 */
.my-component {
    background: blue;
    color: white;
    padding: 20px;
    /* 将这里改为红色，看看即时更新效果！ */
}
```

SCSS 文件会在更改时自动重新编译，生成的 CSS 也会被热重载。

### 图片与静态资源热重载

图片等静态资源同样支持热重载：

```rust
fn Header() -> Element {
    rsx! {
        img { src: asset!("/assets/logo.png") }
    }
}
```

当您编辑 `/assets/logo.png` 时，更改会即时反映在运行的应用中。

### Tailwind CSS 集成

当您启动应用时，DX 会自动下载并后台启动 Tailwind CLI。如果在项目根目录检测到 `tailwind.css` 文件，Tailwind 监听器会监视您的 Rust 代码更改，然后重新编译输出的 `/assets/tailwind.css` 文件。
![Tailwind](./images/tailwind-inline-dxh7fbcc4138a89519c.mp4)

您可以通过项目 `Dioxus.toml` 中的 `tailwind_input` 和 `tailwind_output` 配置字段，手动自定义 Tailwind 输入和输出文件的位置。
